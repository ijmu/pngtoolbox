Settings

Choosing the quality value

WebP's quality slider behaves like JPEG's in shape but buys more per point. Between roughly 75 and 85 the file stays small while artefacts stay out of sight for photographic content; pushing toward 95 multiplies the file for changes that are hard to see at normal viewing sizes. For cutouts with soft edges, inspect the result at 100% zoom after converting — the semi-transparent edge pixels are where a low quality setting shows first.

Unlike the PNG-to-JPG route, nothing is flattened here: WebP stores an alpha channel, so the queue rows still report EXIF absence and the output keeps every transparent pixel. If a browser cannot encode WebP at all, the affected rows say so and fall back to PNG rather than pretending.

Questions

PNG to WebP FAQ

Does WebP keep transparency?

Yes. WebP supports a full alpha channel, so a converted cutout remains a cutout — no fill colour is involved. This is the main advantage over the PNG-to-JPG route.

Why did my logo get larger?

WebP encodes lossily by default, spending bytes to describe pixels it could have stored exactly. On flat-colour graphics a lossless PNG is already near-optimal, so the re-encode adds overhead. Keep graphics as PNG.

Does conversion improve quality?

No. Conversion changes the container and the compression; it cannot reconstruct detail. The value is in the size reduction, not in any quality gain.

Are my images uploaded?

No. Conversion runs locally in this browser with the canvas API — your files are never transmitted to a server.

Which browsers accept WebP files?

Every current browser renders WebP, but upload forms, CMS builds, and desktop applications still reject it in many places. Convert for the destinations that accept it, and keep the PNG as the master copy.
